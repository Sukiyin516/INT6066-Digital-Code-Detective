# INT6066《数字迷案》｜A · 游戏与技术

**供小组用于 Lesson Plan、Poster 和 Presentation。** 功能以当前 V3 Demo 为准。试玩观察来自项目组邀请的三名小学三年级学生，课堂成效尚未验证。

## 1. 游戏介绍（Game Overview）

《数字迷案》是一款面向小学三年级学生（Grade 3 Students）的互动侦探解谜游戏。项目选用人教版《数学》三年级上册「数字编码」作为教学内容，目标是让学生理解编码规则、利用编码信息进行推理，并将读码方法迁移到新情境。教材出处沿用小组教学框架，正式提交前可核对所用版次和页码。

| 关卡 | 学生任务 |
|---|---|
| **Challenge 1 — Identify the Suspect** | 从残缺身份证和邮政编码提取信息，对照六位嫌疑人的资料，找出最符合线索的人，并说明理由。 |
| **Challenge 2 — Find the Missing Ruby** | 查阅小区编号登记表和房屋编码规则，分段读出神秘纸条上的地址，从四个地点中选择搜查地点。 |

## 2. 游戏操作方法（Game Instructions）

**第一关｜锁定嫌疑人**

1. 打开游戏，阅读案情，点击「进入调查室」。点击房间中的放大镜热点可打开桌上证物、墙上的嫌疑人资料和右侧书架。左上角「侦探笔记」可回看已取得的线索，左下角显示进度。
2. 点击「残缺身份证」（证物 A），点击整张知识 Tip 的标题栏或右侧「点击查看」展开，点击「收起提示」折叠。选择「开始解密」，对照身份证和知识图，回答登记性别及出生年代两题。**每答对一题**，对应线索自动写入笔记。
3. 点击「未寄出的信」（证物 B），展开「知识 Tip · 邮编怎么读？」，在图下点「去查邮编」。也可从书架直接打开查询簿。输入信封上的六位邮编，点「查询邮编」。成功查询本案邮编后，城市线索自动记入笔记。
4. 点击「调查嫌疑人」，对照六人的登记性别、出生年代和联系城市。可点「先划掉」「加回来」或「选这个人」。从六人资料点「写第一关报告」，或用调查室右上角「提交调查」进入报告。选择一位嫌疑人，勾选支持判断的线索，再点「提交报告」。
5. 首次错误时，系统鼓励重新核对，点「重新调查」回到六人资料。第二次起可自行展开「查看提示」，提示仅说明如何比较三类线索。证据、已读 Tip 和调查选择会保留。嫌疑人及理由均符合判定条件时，出现「挑战一完成！」。
6. 点「进入下一步调查 →」。神秘纸条出现后，点击「继续调查 →」收集纸条并进入第二关。

**第二关｜寻找失踪的红宝石**

1. 查看纸条编码 `02 - 05 - 03 - 402`。纸条收集后可在桌面或侦探笔记回看，第二关进度从 **1/3** 开始。
2. 点击右侧书架「编码资料库」，分别打开「小区编号登记表」和「TIP 03 · 房屋编码规则」。用登记表解释首段，再按房屋规则解读楼栋、单元、楼层和房号。查看两份资料后达到 **3/3**。
3. 点右上角「提交搜查地点」，从四个地点中选一项，点击「确认地点」。答题时可选「查看侦探笔记」，优先回顾已读的第二关资料。关闭笔记会回到答题并保留当前选项。选错可回去核对并重试，选对可查看结案报告。

**笔记与进度的区别。** 两关共用「解密线索」和「看过的知识 Tip」。笔记只显示已获得的结果与已读材料。第一关 HUD 的 3/3 计算的是打开过的三处资料（身份证、信封、邮编查询簿），不代表已经解密、成功查邮编或通过报告。

## 3. 学生试玩与必要修改（Prototype Testing & Improvements）

三名三年级学生参与试玩。以下是观察到的操作和理解障碍，没有记录可用于比较学习增益的前后测数据。

| 发现的问题 | 修改措施 | 当前实现状态 | 教育目的 |
|---|---|---|---|
| 有学生不知道点哪里 | 放大镜热点、整张可点击的 Tip、明确的主按钮和分步任务提示 | **A 已完成**。证物 A、B 和查询簿均有下一步引导 | 降低操作负担，让注意力回到证据 |
| 听过「单数／双数」，尚不熟悉「奇数／偶数」 | 在身份证知识图使用熟悉的表达 | **A 已完成于图片**。当前加载的图写有「单数是男／双数是女」 | 连接先备知识（Prior Knowledge） |
| 寻找第 17 位耗时 | 用颜色区分身份证编码分段，在知识图用文字及箭头标示第 17 位，练习时同时展示证物和知识图 | **A 已完成**。箭头指向三位顺序码的末位 | 提供视觉支架（Visual Scaffolding） |
| 调查时需要回看和修正（设计回应） | 简化笔记为已获线索和已读 Tip，报告错误时分两步反馈 | **A 已完成**。首次鼓励复查，第二次起提供可选方法提示 | 支持回顾、反思和重试 |
| 熟悉用语仍未覆盖全部界面 | 核对报告理由、回顾文案和知识图替代文字 | **B 尚未统一**。报告理由和替代文字仍出现「奇数／偶数」中的正式术语 | 保持学生端语言一致，并兼顾可访问性 |
| 学生是否能更快找到第 17 位尚未复测 | 用当前版观察学生能否自主定位，再决定是否给证物本身加位号或位置标记 | **B 待复测**。证物图有数字格，但未见单独的第 17 位序号标记 | 减少机械数位，同时保留推理任务 |

**设计记录与现版差异。** 教育设计记录提出先完成两题、查得本案邮编并选定人物才开放报告，且拟将入口改名「提交调查结论」。当前代码没有这组前置限制，六人资料仍显示「写第一关报告」。报告表单要求选择一名嫌疑人，再由现有规则核对嫌疑人和理由。课堂按完整学习顺序引导，汇报时将前置门槛列为待确认的设计提案。

## 4. AI 辅助开发（AI-Assisted Development）

| **Codex — Implementation and Iterative Optimization** | 辅助实现网页、点击热点、弹窗、知识 Tip、解密题、查询和笔记；按需求迭代 UI、流程与反馈，并调试交互。 |

**Student-facing AI（学生直接使用 AI）。** Demo 运行时使用预设游戏资料和判断规则。学生端没有聊天、模型调用或实时生成式教学功能，离线可以使用。

## 5. 技术实现（Technical Implementation）

| 模块 | 实际做法 |
|---|---|
| 游戏页面与场景 | 使用原生 HTML、CSS 和 JavaScript。背景图上叠放可点击的放大镜按钮，热点位置随场景比例调整。运行无需服务器或安装依赖。 |
| 热点与知识卡 | JavaScript 根据热点打开网页弹窗。知识 Tip 使用浏览器自带的展开／收起控件。背景、证物和知识图均为本地图片。 |
| 判题与查询 | 练习题按预设选项检查，邮编用内置表做精确匹配，报告核对所选人物及理由组合，第二关核对所选地点。 |
| 进度与恢复 | 浏览记录、已读 Tip、已获线索、选择、错误次数和关卡状态等保存在当前浏览器的本地存储（localStorage）。重新加载时读回存档。第二关回顾笔记时的临时地点选择随返回保留，未提交选择不承诺刷新后恢复。 |
| 两关衔接 | 正确报告触发完成弹窗，学生主动继续后播放纸条过渡并收集纸条，随后切换第二关热点和任务。 |

## 6. 游戏如何支持学习（Educational Value）

| 游戏功能 | 对应教育作用 |
|---|---|
| 知识 Tip | **Scaffolding**。用分段图、箭头和简短提示帮助学生理解每段数字。 |
| 证物解密 | **Guided Inquiry**。学生观察、提取信息、比较并验证判断。 |
| 第二关房屋编码 | **Knowledge Transfer**。将「先分段，再按规则解释」的方法应用于新的地址编码。 |
| 错误反馈与重试 | **Formative Assessment**。首次鼓励自主复查，之后提供可选方法提示，帮助学生修正判断。 |
| 两人共用平板 | **Pair Work**。课堂可安排一人操作、一人解释依据，再交换角色。这是课堂安排，游戏没有多人协作功能。 |
| 侦探笔记 | 汇总已获线索和已读材料，帮助学生回顾、比较和整合证据。 |

小组既有框架包括 **TPACK、ICAP、Guided Inquiry-Based Learning、Scaffolding、Pair Work、Formative Assessment、Bloom’s Taxonomy（Understand → Apply → Analyze）与 Knowledge Transfer**。上表说明功能如何服务于这些教学安排，不把设计目标写成已验证的学习成效。

## 7. 展示版本准备（Demo Preparation）

- **启动与设备**：完整解压游戏目录，双击 `index.html`，或在 Windows 双击 `打开游戏.cmd`。建议用 Chrome 或 Edge 桌面横屏投影。课堂用平板时，提前在实际设备验证本地打开、点击和阅读尺寸。
- **最短连贯展示路径**：进入调查室 → 身份证知识卡与解密 → 信封知识卡与查邮编 → 六人资料、选人并提交报告 → 收集纸条 → 打开两份书架资料 → 选地点并查看结案报告。错误反馈可单独示范一次或用截图带过。
- **准备**：在同一台演示电脑预跑一遍。开场前确认旧进度是否需要通过「重新开始」清空。准备两关截图备用。若需单独快切第二关，离线文件可用 `index.html?dev=stage2` 进入开发测试模式，该模式独立于课堂存档。
- **展示限制**：第一关报告入口没有设计记录中的强制前置门槛。第 17 位在证物上的可见性、正式术语残留和窄屏阅读体验需在演示设备上核对。HUD 的 3/3 应解释为资料浏览进度。
- **核验**：当前源码及游戏素材的临时副本已在 Edge 中通过离线浏览器测试，覆盖两关流程、错误重试、纸条过渡、答题回看、结案和刷新恢复。测试脚本有两处按钮定位需更新，本次只在临时副本里调整。原项目测试未改。另有 96 种报告组合的规则测试通过。实体平板和课堂投影尚待试跑。

## 9. 约一分钟展示讲解稿（Presentation Script）

**English**

This is *Digital Mystery*, an offline game for Grade 3 students. In Challenge One, students examine a damaged ID card and an envelope. They use coding tips to read the clues, compare six suspects, and explain their choice. If their report is incorrect, they first get a chance to rethink it. A later attempt offers an optional hint. In Challenge Two, they use the same way of thinking to decode a new address and find the missing ruby. The detective notebook saves clues and lets students review what they have read. We used AI tools to help design and build the demo. During play, the game uses fixed rules and works offline.

**中文版**

这是《数字迷案》，一款面向小学三年级的离线游戏。第一关，学生观察残缺身份证和信封，用知识提示读出线索，对照六位嫌疑人，并解释为什么这样选。提交错误时，系统先请学生重新思考，再次答错后才提供可选提示。第二关，学生把同样的读码方法用到新的地址编码上，寻找失踪的红宝石。侦探笔记会保存已获得的线索，方便学生回顾。我们使用 AI 辅助设计和制作，学生游玩时由预设规则判题，可离线运行。
